Sequence Diagram Web Component

A custom element (<sequence-diagram>) that renders interactive sequence diagrams from JSON data.
Uses React + React Flow inside Shadow DOM — zero framework dependencies on the host page.

IIFE + ESM Shadow DOM 7 Palettes 3 Themes Use npm run dev or npm run serve:dist to start
1

Basic Usage

Pass data via an embedded <script type="application/json"> child. The component auto-detects and parses it. Theme defaults to system, palette to classic.

2

Property API

Set element.data (object or JSON string) to update the diagram dynamically. The button below replaces the data; after 3 seconds the diagram auto-reverts.

3

Theme Modes

Three instances with theme set to light, dark, and system (follows your OS preference). All share the same palette (ocean) for fair comparison.

Palette Gallery

All 7 built-in palettes. Use the per-instance dropdown to switch any diagram's palette at runtime.

Sequence Features

Sync, async, return, self-call, note, activation, divider, and all fragment kinds. All loaded from public/examples/*.json.

Events

Click any message arrow or participant header. The component dispatches DOM events (sequence-message-click, sequence-participant-click, sequence-fragment-click). Event detail is formatted as JSON below.

7

Responsive Layout

Drag the resize handle to change the diagram width. The component uses ResizeObserver internally and re-fits the viewport on resize.

width: 100%
8

CSS Isolation

The component is wrapped in a hostile host environment: aggressive CSS reset, Comic Sans, bright background stripes, lime/pink borders, all: unset on all children, and small SVGs. Shadow DOM must protect the component internals.

The component inside the hostile CSS block above should render correctly.

9

Error Handling

Each chip loads an invalid diagram with a specific failure mode. The component renders an error card in place of the diagram and dispatches sequence-error with structured details. Click Reset to return to the valid example.

10

Multiple Instances

Six independent instances on the same page. Each owns its own Shadow DOM, state, and events. Changing one does not affect the others.
